# Decisions log

Format: date - question - choice - alternatives.

## 2026-10-19
1. **Toolchain** - MSVC 2022 + Qt 6.8 minimum (installed: Qt 6.11.2 msvc2022_64, Ninja, CMake 4.4.3). Alternative: keep the MinGW kit (rejected: SMTC/taskbar/COM are awkward with MinGW). Code must not use APIs newer than Qt 6.8.
2. **CMake minimum** - 3.25 (presets v6). Starter had 3.16.
3. **Schema change D1** - `track.home_kind`/`home_id` store the file's home location (SPEC 4.2). Alternative: derive from path (fragile).
4. **Schema change D2** - no UNIQUE on `(container_id, position)` in `album_track`/`playlist_track`; service renumbers in one transaction. Reason: SQLite checks UNIQUE per row.
5. **Schema change D8** - indexes `ix_track_last_played`, `ix_album_year`.
6. **Schema change D10** - `name_key` (casefolded + diacritics-stripped via `Normalizer`) with UNIQUE index on artist/playlist, `title_key` unique per primary artist on album. Reason: SQLite `NOCASE` folds ASCII only.
7. **Rescan vs hash (G6)** - rescan compares size+mtime recorded after the tag write; `content_hash` (source bytes) is never recomputed.
8. **`Result<T>`** - own implementation (C++20 has no `std::expected`); `Result<T, Error>` alias provided.
9. **Add button** - `+` icon with tooltip "Add" (UI doc p.17 vs mock-up).
10. **Starter project** - the Qt Creator starter (`main.cpp`, `Main.qml`, `importedcontent/` Figma hook) is replaced in M0.

## 2026-10-19 (M1 implementation)
21. **Identity key without diacritic stripping** (deviation from D10): `name_key`/`title_key` = trim + NFC + collapsed spaces + `QString::toCaseFolded()`. "Beyonce" and "Beyoncé", "й" and "и" stay different names; only the search key strips combining marks U+0300..036F. Note: Qt's case folding is *simple* folding (ß stays ß, it does not become "ss").
22. **File effects in M1** are recorded as `FileOp`s and handed to `IFileStorage` after the DB commit (spec order is files-then-commit with the journal; M2/M4 replace this). `RecordingFileStorage` is the M1 implementation/test double.
23. **Previews** (`planDelete*`) execute the real operation in a transaction and roll it back; tests assert plan == actual for every delete.
24. **Re-homed primary** stays on the album as the last co-author and the artist becomes hidden (UI doc p.33/38: "the artist becomes hidden but still owns a visible album").
25. **Hidden artists may be co-authors** (SPEC 5.1 allows co-author rows on hidden artists); creating an album makes its authors visible, deleting a visible artist who is only a co-author leaves them hidden on that album.
26. **Tag seeding**: the `tags_seeded` flag is only set when tags were actually copied, so an album without tags does not use up the one-time seeding.
27. **Add to discography** credits the chosen artist (role `main`) if the track does not credit them yet, and moves the file only when the track's home is a playlist (a track already homed in an album keeps its file where it is and gets an extra membership).
28. **Position renumbering** is done row by row in C++ (a single UPDATE with a correlated sub-select reads its own earlier writes in SQLite and gives wrong ranks).
29. **Temporary markers**: while paths are re-computed, rows briefly carry paths starting with U+0001 (`\x01tmp/..`, `\x01new/..`); the integrity checker verifies none are left behind.
30. **No WriterQueue yet**: one synchronous connection per `Database`; the serialised writer and reader pool come in M4 with the worker threads. Repositories only need a `Database&`, so they will not change.
31. **Renames and updates** (artist/album/playlist/track edit, folder renames) are not in M1 (listed under M4); only create, membership and delete operations exist.
32. **Test output on Windows**: test executables write to stdout only when started from a console; under Git Bash/Qt Creator use `-o file,txt` or the Qt Creator test pane. `ctest --output-on-failure` shows failures.

## 2026-10-19 (M2 implementation)
33. **What "never permanent" means in code.** Library content (audio, covers) leaves the library only through `ITrash` (`QtTrash` = `QFile::moveToTrash`). Semplice's own housekeeping files (journal entries, old backups, log rotation, and files that an *uncommitted* operation itself created, e.g. the copies of a cancelled import) may be removed directly, but only through `core/storage/OwnFiles.cpp`. The CTest `no_direct_deletes` fails if any other source file calls a delete API (and `no_direct_deletes_detects_violations` proves the guard works). Rolling back a copy never removes a file that already existed (`dstPreexisting`).
34. **Deletions are phase B**: Trash steps run only after the database commit, because a Recycle-Bin move cannot be rolled back reliably. Before the commit nothing is ever deleted.
35. **Commit marker in the database**: table `op_log` (migration 0002). The operation's DB transaction inserts its uuid, so journal recovery knows exactly whether it committed. Entries of the one-shot `apply()` are flagged `autoCommit` and always roll forward.
36. **`apply()` keeps the given order** (including Trash) because M1's `LibraryService` emits ops in that order. For the two-phase flow of M4, `LibraryService` must be changed so that no later move needs a path that an earlier Trash step would free (e.g. delete track 1, then rename track 2 to "01 - ..." with the same title); M4 will handle this when it switches to `begin()/execute()/finish()`.
37. **Case-only renames** (`abba` -> `ABBA`) are recorded with a temporary `via` name; steps are resumable from any point and decided by exact-case directory listings.
38. **Failure in the middle of a one-shot `apply()`** keeps the journal entry; the next start completes the remaining steps (the database already committed).
39. **Windows hidden attribute** is behind `IFileAttributes`; `WindowsFileAttributes` lives in `platform/`.
40. **`QFile::moveToTrash`** is used as the Windows Recycle Bin implementation; no hand-written `IFileOperation` wrapper (asked for review in the M2 design note).
41. **Corrupt database**: `openLibrary` returns `E_DATABASE_CORRUPT`; the UI offers `LibraryFolder::restoreNewestGoodBackup`, which keeps the damaged files as `library.db.corrupt-<timestamp>` (renamed, not deleted). Backups are checked read-only (`Database::open(path, readOnly=true)`).
42. **Known limitation**: folder-name uniqueness in the database (`dir_name ... COLLATE NOCASE`) only folds ASCII case; two names that differ only by non-ASCII case would clash at insert time. Real clashes are prevented earlier by the `name_key`/`title_key` uniqueness; revisit in M4 if the path layer ever needs it.
43. **Tests that changed**: `SimplePathNamer` was replaced by `SanitizingPathNamer`; the test library fixture can run against a real `FileStorageService`.

## 2026-10-19 (M3 implementation)
44. **TagLib 2.3.2** via `FetchContent` from the official release tarball (URL + SHA-256 pinned in `cmake/TagLib.cmake`; the tarball contains the bundled utfcpp, a git archive would not), static, without zlib/bindings/examples/tests, and WITHOUT DSF/Matroska/MOD/Shorten/TrueAudio. The first configure needs internet access. Our own interface target `semplice_taglib` carries the header folders (TagLib does not export them as a sub-project). TagLib's debug messages go to our log (`SLOG_DEBUG`), not to stderr.
45. **Reading never opens a file for writing**: `TagLib::FileStream` read-only, then the format-specific file class on that stream. Originals stay untouched even on a locked or read-only file.
46. **`legacy8bit` flags** in `TrackTags`: MP3 is read frame by frame; fields from ID3v1 or ID3v2 frames declared ISO-8859-1 are flagged, and only those may be touched by the `EncodingFixer`. Everything else is trusted.
47. **Tag writing**: temp copy `<name>.semplice-tagtmp-<id>` in the same folder -> write with TagLib -> read back and verify (title, artists, genres, album, year, cover) -> atomic replace -> `IFileReleaser` told. No journal entry: a tag write is atomic by itself and its failure never rolls back the database (SPEC 6.2). `TagService::removeStaleTempFiles(root)` (start-up) deletes leftover temp files and restores an original that was set aside when the crash hit the portable replace.
48. **MP3 output**: ID3v2.4, all text frames forced to UTF-8, ID3v1 and APE stripped. WAV: ID3v2.4 chunk, INFO stripped (best effort). Other properties (comments, lyrics, user text frames) are kept because we read the full property map, change our keys and write it back.
49. **WMA** stores only ONE "Author" string: several artists are written joined by `;` and split again on read.
50. **Atomic replace**: `IAtomicReplace`; `WindowsAtomicReplace` = `ReplaceFileW` (platform), `PortableAtomicReplace` fallback (set the original aside, move the new file in, remove the backup). A file held open by another program yields `E_FILE_LOCKED` and nothing changes; the audio backend handshake is the `IFileReleaser` interface (implemented by M5's `IAudioBackend::release`).
51. **EncodingFixer**: only for flagged fields; only text below U+0100 that looks broken (>= 2 non-ASCII characters making up >= 60 % of the characters that are non-ASCII or ASCII letters); candidates UTF-8 (double-encoded), CP1251, GBK (GB2312 subset only), Shift-JIS, EUC-KR, Big5, each checked structurally, decoded without errors and judged plausible (script majority, no Latin/Cyrillic mixing inside a word, kana is a strong Japanese signal). Known limit, documented in the code and in `docs/design-notes/M3-tags.md`: Han-only text can be valid in several CJK code pages and Hangul/Big5 bytes are often also valid GBK; the first plausible page in the configured order wins and the other readings are returned as `alternatives` for the Add Album form. The real Windows tables are covered by `tst_windows_platform`.
52. **Genre vocabulary**: 76 genres in `resources/tags/genres.json`, generated once from a table and now maintained by hand; validated at load (unique slug keys, four names, aliases unique across all genres and languages, symmetric and disjoint relations, complete ID3v1 table 0-191) and in tests; `docs/GENRES.md` is generated from it by `scripts/genres_to_markdown.ps1`. ru/zh_CN/ja names are machine drafts.
53. **`GenreMap`** understands `17`, `(17)`, `(17)Rock`, names in all four languages, aliases, and lists separated by `; / , | +` or ` & `; unknown text is ignored.
54. **Cover rules**: `cover.*` before `album_cover.*` (jpg, jpeg, png; names case-insensitive; content must really be JPEG/PNG; only the folder itself), user choice > folder file > embedded picture of the FIRST track; stored names are always `album_cover.<ext>` etc. Writing a cover file never overwrites.
55. **Test audio files** are built byte by byte in `tests/tools/TestAudioFiles` (MP3, FLAC, OGG Vorbis with hand-made pages and CRC, M4A atoms, WAV, WMA/ASF with file- and stream-properties objects): no encoder dependency.

## M4 - Import and library services
57. **One protocol for every file-touching operation** (SPEC 4.5), implemented once in `LibraryService::transact`: DB transaction opens -> rules/rows change and the file operations are collected -> journal entry (`begin`) -> phase A (create folders, copy, move; cancellable; progress) -> tags written into the NEW files -> commit marker in `op_log` -> **COMMIT** -> phase B (Recycle Bin, journal removed) -> tags of EXISTING files synced. A cancel or error before the commit undoes both sides; a crash is repaired at the next start by the journal + `op_log` oracle. Tested by crashing at every checkpoint of an import and of a rename.
58. **`track.tags_dirty`** (migration 0003): any change that should change a file's tags marks the track; the tag write happens after the commit and never rolls the edit back. A locked or read-only file leaves the flag set, the edit result lists the track in `tagWriteFailed`, and Rescan (or the next start) retries. Files of NEW tracks are tagged in place before the commit because nobody can hold them open yet.
59. **Trash vs. reuse of a path in one operation**: the Recycle Bin is only used after the commit, so a delete whose path is reused by a later move in the same operation is rewritten to "move aside, trash after the commit" (`rewriteTrashConflicts`). Needed for renumbering after deleting a track.
60. **Import scans and hashes everything up front** (SHA-256 of the source bytes) so duplicates are known before the form is shown. A duplicate is never copied again: the existing track is reused and only added to the new album/playlist. The stored hash stays the hash of the SOURCE and is never recomputed (decision 7), so a stray *tagged* copy of a library file is not recognised as a duplicate by Rescan; a stray copy of the original source file is.
61. **Artists in forms are names**: credits given by name are found or created in the same transaction (hidden unless they author an album). A playlist track without any artist gets the hidden artist "Unknown artist" (the file name rule needs one). The splitter proposes (`feat.`, `ft.`, `featuring`, `;`, `&` unless the whole text is an existing artist) and never splits on `,` or `/`.
62. **Classification**: shared album tag, or more than half of the tracks sharing one artist, or an artist page open -> album; 1-3 tracks Single, 4-7 EP, 8+ Album; otherwise a playlist. A missing year is left for the user (the form cannot be committed without one).
63. **Covers**: user choice > file next to the music > picture embedded in the first track (extracted to `.library/tmp`, copied, and swept at start-up). Stored as `album_cover.<ext>` / `playlist_cover.<ext>` / `artist_avatar.<ext>` and never overwritten; replacing one sends the old file to the Recycle Bin after the commit.
64. **Rescan** (incremental, size + modification time): unknown files are MOVED into a new playlist `Rescan <yyyy-MM-dd HH-mm>`; unknown copies of a library track go to the Recycle Bin; rows whose file is gone are deleted with the normal cascades; unreadable files stay where they are. **Mass-removal guard**: if more than max(20, half of all tracks) are missing nothing is removed (an unplugged drive must not wipe the library) unless `allowMassRemoval` is set. Missing rows are removed from the back of each folder to the front, because deleting a track renumbers (renames) the files behind it and a missing file cannot be renamed. Rescan also retries `tags_dirty` and runs maintenance (PRAGMA optimize, VACUUM when more than 20 % of the pages are free, backup rotation).
65. **`LibrarySession`** owns everything of one open library (database, journaled storage, tag service, services, search index) and is destroyed to switch libraries. `LibrarySwitcher` implements the folder rules of SPEC 6.6: empty folder = new library, library = open, anything else = `E_FOLDER_NOT_EMPTY`; the path is stored in the settings (`library/path`) only after the library opened. A library written by a newer Semplice fails with `E_SCHEMA_TOO_NEW` without being touched.
66. **Search index** is rebuilt at session start and follows `libraryChanged` signals; it is never rebuilt after each edit.
67. **`semplice_libtool`** (`tests/tools`, Windows only): imports, rescans and checks a real library from the command line, with the real Recycle Bin, so M4 can be tried on a COPY of real music before the UI exists.

## M5 - Playback core
68. **Where the pieces live**: `core/playback` (Qt Core only): `IAudioBackend`, `PlayQueue`, `PlaybackService`, catalog/store/recommender interfaces, `SystemIntegration`; `platform/`: `QtAudioBackend` (the only user of Qt Multimedia), `WinSmtc`, `WinThumbBar`. Design note: `docs/design-notes/M5-playback-core.md`.
69. **Queue**: ordered groups; `PlayRequest.afterEnd` (Stop for playlists and search, Recommend for album / artist / carousel) is chosen by the caller. A carousel item started from inside the carousel is one group per carousel item; "play all" on a carousel is one `Carousel` group whose entries carry their own source album/playlist (`QueueTrack.sourceId/sourceKind`) so each is registered in Recently Played. Discography is one group, entries carry the album.
70. **Next / Previous**: Next on the last track continues into the next group, then into recommendations, otherwise it is disabled; with repeat-all it wraps inside the group. Repeat-one only applies when a track ends by itself; the Next button still moves on. Previous: after more than 5 s restart the track, otherwise walk the real played history (also under shuffle); with an empty history it goes to the previous track or, at the start of a group, into the last track of the previous group (carousel "go back"); disabled at the very start. Skipping while paused starts playing the new track (DEFAULT, not in the spec).
71. **Shuffle-bag**: switching shuffle on keeps the current track first and permutes the tracks of the group not yet played in this pass; off restores the natural order from the current track; every new pass (repeat-all) or new group gets a fresh bag whose first track differs from the one that just ended. Shuffle never leaves the current group. Recommendation groups are never shuffled.
72. **Statistics**: listening time is accumulated from position updates that advance by at most 2 s (seeks, pauses and frozen windows do not count). At `min(30 s, 50 % of the duration)`: `play_count++` / `last_played_at` for every kind of playback, and Recently Played gets the source container (once per visit of a group; discography and carousel register each album/playlist separately). "First track" of the spec = the first track of that container that reaches the threshold. Recommended tracks count as plays but never touch Recently Played. Repeat-one counts every listen.
73. **Unplayable files**: the catalog says a file is gone, or the backend reports an error (also during playback): the track is removed from the queue and the next one is tried; the whole batch gives ONE `tracksSkipped(n)` signal. Nothing playable left = stopped.
74. **Deleted tracks**: `PlaybackService::revalidate(touched)` (fed from the `ChangeSet` of `libraryChanged`) removes tracks that no longer resolve; the current one is replaced by the next without changing play/pause.
75. **Recommendations are an interface** (`IRecommendationSource::pick`) until M9; the service keeps 3 tracks of look-ahead in the `Recommendations` group, excludes what is queued, and stops when the source returns nothing.
76. **Persistence**: `kv('session')` holds the queue (groups, order, bag, played flags, history, modes, after-end rule) and the position; saved on every track / state / mode / queue change and by `persist()`; `restore()` drops missing tracks (one banner), loads PAUSED and seeks to the stored position (0 when the current track is gone). Volume (default 0.5) and mute are kept in `settings.ini` through `ISettings`.
77. **Audio backend**: `QtAudioBackend` = `QMediaPlayer` + `QAudioOutput`; slider value converted to linear amplitude; positions polled every 250 ms; Qt has no gapless API, so `preload()` is accepted and ignored (short gap allowed by SPEC 7.1). `releaseFile()/fileReady()` implement the tag-write handshake (file closed and re-opened at the same position, play state kept).
78. **SMTC** uses the real WinRT API through hand-declared COM interfaces (MinGW headers lack the definitions; vtable layouts and IIDs copied from the Windows SDK 10.0.26100 headers), so one code path builds with MinGW and MSVC. Thumbnail passed as a `file:` URI. Global media keys come with SMTC. `WinThumbBar` draws its icons with `QPainter` and picks light/dark from the system colour scheme.
79. **`semplice_playtool`** (`tests/tools`, Windows): plays a real library through the real audio device with the real SMTC / thumbnail buttons and a small keyboard window; used for the manual checks before the UI exists.

## M6 - UI shell and panels
80. **Threads**: the library session (database, journaled storage, import/rescan/edit services, search index) lives on one engine thread (`LibraryEngine`); the GUI thread owns the audio backend, `PlaybackService`, SMTC and the thumbnail buttons plus its own database connection for single-row playback queries (resolve a track, record a play, save the session). SQLite WAL and `busy_timeout` serialise the rare concurrent write. The engine reaches the audio backend (tag-write handshake) through a blocking queued proxy.
81. **Lists** (`LibraryQueries`) are one SQL statement per tab; the rows travel to the GUI as plain value vectors and replace the model in one step. Sorting: Alphabet ascending = A to Z (down arrow), Recent descending = newest first (default, never stored), Year only for albums; choosing the active key flips the arrow; hidden artists and the Unsorted album are never listed. Album type filter: all shown by default, hiding the last visible type shows all again. Tab and view mode per tab are stored in `settings.ini` section `[ui]`.
82. **Play rules from the lists** (UI doc p.5-16): the picture/avatar plays (artist = whole discography, newest album first, as ONE group whose entries carry their album; album; playlist), the title opens the page, the artist line of an album opens the artist card; the extra-large view has no names (playback only). Search results follow the same rules; a track hit plays a queue of just that track and never starts recommendations. A track hit registers its home container in Recently Played like any playback.
83. **Navigation**: `NavigationHistory` (100 pages max, no duplicates in a row, opening from the past drops the forward part) behind the hotbar arrows and Alt+Left/Right; M6 only routes: the middle window shows which page was asked for (real pages come in M7/M8). Clicking anything that opens a page closes the popups.
84. **Popups**: search and queue popups are exclusive, close on any click outside, Esc, or when a page opens; the search text survives closing (until exit). The search runs on the engine thread after a 120 ms pause in typing; answers for older texts are dropped by a token. Five hits per category, "Show more" lists the whole category.
85. **Banners**: `BannerQueue` keeps three at most, newest below, nothing expires. Texts are built in `BannerVm` from message keys (translated, with plural forms) so the core holds no user text. Used for: tracks skipped (one per batch), folder not empty / not found, library from a newer version, library cannot be opened, interrupted operation completed, item could not be played, and the generic "Error -1".
86. **Start-up states** (`AppController::Startup`): loading, no library yet (first launch card "Select folder"), stored folder missing ("Locate your library"), ready, failed (stored library unusable: card plus banner). While not ready everything is dimmed and the card is the only thing that reacts (UI doc p.3). A refused folder (not empty) leaves the current state and shows a banner; the stored path is written only after a library opened.
87. **Pictures**: `image://cover/<relative path>` and `image://cover/file?path=...[&embedded=1]`; decoded on the thread pool, scaled to the requested size (never enlarged), 64 MB memory cache, small PNGs in `.library/covers`. The player cover follows UI p.21: picture inside the file, then the album cover, then the placeholder (a playlist cover is never used for a track).
88. **Keyboard** (SPEC 8.7): Space and M are ignored while a text field has focus; Ctrl+Left/Right, Ctrl+Up/Down (+-5 %), Ctrl+F, Alt+Left/Right, Esc.
89. **Release-only crash found and fixed** (in M5 code, first seen when the app ran in a MinGW release build): the hand-declared WinRT interfaces in `WinSmtc.cpp` sat in an anonymous namespace; GCC then concludes that no object of those types can exist and compiles every virtual call on them into a jump to nothing. They live in a named namespace now, the COM calls no longer pass interface pointers through `void**` aliases, and `semplice_platform` is built with `-fno-strict-aliasing`. Lesson: run the app (not only the tests) in Release on every compiler.
90. **Testing aids in `Semplice.exe`** (no effect in normal use): `--grab <png>` with `--grab-delay <ms>`, `--dev-play <kind>:<id>`, `--dev-tab <n>`, `--dev-popup search|queue`, `--dev-search <text>`, `--bench-scroll` (scrolls the library list and logs frame times). `semplice_gen --library <folder>` creates a library folder around a synthetic database so the app can open it (the audio files do not exist; use it to look at lists and scrolling).

## M7 - Home view
91. **Greeting** (SPEC 8.6, DEFAULT reading): an empty library always says "Welcome, {name}!" (UI p.23); with content an occasion wins (New Year Dec 31 - Jan 2; first day of spring/summer/autumn/winter on Mar 1 / Jun 1 / Sep 1 / Dec 1), otherwise the time of day (morning 05-11, afternoon 12-17, evening 18-04). "Welcome back" is not used: the occasion and time-of-day texts take its place. Texts are drafts in English and translated (machine drafts for ru/zh_CN/ja).
92. **Categories**: six types (artist discography, year, decade, genre, "Your Playlists", "Your Albums"). Minimums (DEFAULT where the spec is silent): year / decade / genre / "Your Albums" >= 5 albums (spec), artist >= 3 albums, "Your Playlists" >= 2 playlists. Max 50 items. The Unsorted album and hidden artists are never counted. Five carousels at launch, three more per request while scrolling; **no type repeats until every type with unused content has been used once**, then the cycle restarts; an instance (artist, year, ...) is never shown twice in a session. The artist carousel and the year / decade / genre carousels show a random sample in random order, "Your ..." the most recent items.
93. **Stability**: the generated categories are kept while the page is refreshed (a library change re-reads the SAME categories, their items are re-sampled); a played track refreshes only Recently Played; the generator forgets everything when the library closes, so the next launch makes new ones.
94. **Recently Played** is always the first section (an empty hint while there is nothing), up to 50 albums and playlists, newest first; it appears as soon as something has been listened to (the 30 s / 50 % rule of decision 72).
95. **Carousel**: `PathView` with five visible tiles, circular, centre tile enlarged and in front; drag or wheel turns it, a click on the middle tile plays it as a carousel queue (one independent queue per carousel item, UI p.53), a click on a side tile brings it to the middle. Under the middle tile: title (opens the page) and artists (opens the artist); the discography carousel shows only the album title; playlists show only the title.
96. **Category page** (UI p.25): label "Carousel", big title, statistics ("15 albums, 6 h 20 min"; "items" when albums and playlists are mixed), a play button (ONE queue of everything, header = carousel name, clickable back to the page) and every item as a tile (all items, not just 50); on a discography page each tile shows year and album type; clicking a tile plays that item as a carousel queue starting there. Keys: `recent`, `artist:<id>`, `year:<y>`, `decade:<first year>`, `genre:<tag>`, `playlists`, `albums`.
97. **Drop zone** (UI p.29): while files are dragged over the middle window the title becomes "Import", the page is blurred and an import icon appears; a drop opens the Import page, which is a placeholder until M8 (the dropped files are not read yet).

## M9 - recommender
112. **Structure**: `core/recommend/` = `RecommenderConfig` (all weights), `scoreTrack` (pure), `Selector` (pool + random in, track ids out), `loadRecommendationPool` (4 bulk queries), `LibraryRecommendationSource` (the `IRecommendationSource` the player uses). Details in `docs/design-notes/M9-recommender.md`.
113. **A track's tags** = its own tags + the tags of the albums that contain it; artist tags are not mixed in. Year = the earliest album that contains it.
114. **Selection**: score every candidate, keep the best 100, choose by chance weighted by score (the worst of the 100 keeps a small chance). Variety uses the track's first album: never the same album twice in a row, at most 2 per album in any 10 positions; playlist-only tracks are never limited. If no candidate satisfies the rules, the window rule is dropped first, then the "twice in a row" rule.
115. **Relaxation order** when fewer than 2 candidates remain: (1) tracks of the seed albums are allowed, (2) tracks already recommended before are allowed again (the "used" set restarts), (3) otherwise nothing is returned and the queue ends.
116. **Pool**: built on a worker thread (own read connection) when a library opens and again after every library change; the pick itself uses memory only. If the first pool is not ready when it is needed, the pick waits for it. The "used" set survives a rebuild.
117. **Speed on 200k tracks** (Release, this machine): reading the pool and one pick about 0.7 s in total on the worker, one pick of 3 tracks about 9 ms. To stay near the GUI budget a pool larger than 20,000 candidates is sampled (random 20k) before scoring; the effect is that a very rare signal (one artist's few tracks among 200k) may not be seen in a given pick. Tune `maxScored` if that turns out to matter.
118. **Debug view**: `semplice_recotool <library folder> --album <id> | --playlist <id> [--top N]` prints the best candidates with every score component and the time of one pick. It is a separate command-line tool, not part of the app.
